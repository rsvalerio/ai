# OWN rules

## Ownership & Borrowing (typical severity: Medium--High)

- **OWN-1.** Prefer `&T` over `&mut T`; smallest scope possible. The same applies to mutability in time, not just in scope: where a value is mutated only while being prepared, narrow it afterwards by rebinding (`let mut data = get_vec(); data.sort(); let data = data;`) or by building it inside a block that returns it (`let data = { let mut d = get_vec(); d.sort(); d };`), so the compiler — rather than a comment — guarantees nothing mutates it later
- **OWN-2.** *Retired.* Do not reuse this ID for new rules; old findings may reference it.
- **OWN-3.** Return owned data to avoid lifetime leakage
- **OWN-4.** `Cow<T>` for conditional ownership
- **OWN-5.** *Retired.* Do not reuse this ID for new rules; old findings may reference it.
- **OWN-6.** Prefer `Option<&T>` over `&Option<T>`
- **OWN-7.** `AsRef`/`Borrow` to accept owned or borrowed. In *function* signatures this means `impl AsRef<str>`, `impl AsRef<Path>`, `impl AsRef<[u8]>` in place of separate `&str`/`String` overloads. Two limits: (1) do not push the bound onto a *type* — `struct User<T: AsRef<str>> { name: T }` makes every downstream signature generic for no benefit, so store a `String`; (2) where the function takes ownership anyway (`fn new(x: impl AsRef<str>) -> HoldsString`), `AsRef` buys ergonomics at the cost of a copy — accept `String`/`Vec<u8>` on high-volume paths and keep `AsRef` for convenience APIs. Where the parameter is a plain reference rather than a generic, borrow the *borrowed* type, never a reference to the owned one: `&str`, `&[T]`, `&Path`, `&T` in place of `&String`, `&Vec<T>`, `&PathBuf`, `&Box<T>`. The owned type already carries one level of indirection, so `&String` is two hops to the bytes, and it also rejects callers who only hold a slice — `String` coerces down to `&str` implicitly, but a `&str` will not coerce back up. `clippy::ptr_arg` catches the `&String`/`&Vec<T>`/`&PathBuf`/`&Cow<_>` cases; `&Box<T>`, `&Rc<T>`, and `&Arc<T>` parameters it does not
- **OWN-8.** If you're cloning to satisfy the borrow checker, rethink ownership design — mechanical detection of redundant clones is handled by `clippy::redundant_clone`; this rule covers the design smell of cloning as a workaround for lifetime issues
- **OWN-9.** `Rc` for single-thread sharing; `Arc` when crossing thread boundaries; `Weak<T>` to break cycles. For shared-state primitive selection (`Arc<Mutex<T>>` vs `Arc<RwLock<T>>` etc.), see CONC-1
- **OWN-10.** `RefCell<T>` for single-thread interior mutability only; enforces borrowing rules at runtime (panics on violation). For cross-thread sharing, see CONC-1; for the security angle of `unsafe impl Sync` with `RefCell`, see SEC-24
- **OWN-11.** Deref early in chains to reduce `&` noise (e.g., `let val = *wrapper;` before chaining methods instead of `(&wrapper).method()`)
- **OWN-12.** Implement `Deref` only for transparent wrappers and smart pointers; never use it to simulate OOP inheritance — implicit method resolution through deref coercion creates confusing APIs and hides ownership semantics
- **OWN-13.** When the borrow checker rejects code because the *whole* struct is borrowed to reach one field, split the struct rather than reaching for `.clone()` (OWN-8). Rust borrows fields disjointly — `&mut db.connection_string` and `&db.timeout` coexist happily — but a function or method taking `&Database`/`&self` borrows all of it, and that is what collides. Two fixes, in order: (1) take the fields the callee actually needs (`fn print(conn: &ConnectionString, timeout: Timeout)`) instead of the whole struct, which also documents the real dependency; (2) where several fields move together, group them into a smaller struct composed back into the parent, so the parent can be borrowed a piece at a time. Applying (2) to a set of fields with no cohesive name produces worse abstractions, not better ones — if the sub-struct cannot be named without inventing a `…Data`/`…Info` suffix (API-1), the answer is (1) or a narrower `&mut` scope
